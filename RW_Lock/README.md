# Отчёт по задаче 3. Собственная блокировка чтения-записи

## 1. Постановка задачи

Требуется создать собственную реализацию типа `rwlock` и функций `rdlock`, `wrlock` блокировки чтения-записи, апробировать её на примере односвязного списка и сравнить производительность с библиотечной `pthread_rwlock_t`.

## 2. Реализованные алгоритмы

### 2.1. Блокировка чтения-записи `my_rwlock_t`

Блокировка построена на одном мьютексе и двух условных переменных. Структура содержит:

| Поле | Назначение |
|---|---|
| `pthread_mutex_t mutex` | защита остальных полей структуры |
| `pthread_cond_t readers_cv` | ожидание читателей |
| `pthread_cond_t writers_cv` | ожидание писателей |
| `unsigned active_readers` | число потоков, читающих в данный момент |
| `unsigned waiting_readers` | число потоков, ожидающих блокировку на чтение |
| `unsigned waiting_writers` | число потоков, ожидающих блокировку на запись |
| `int writer_active` | признак работы писателя (0 или 1) |

Политика — приоритет писателей: при наличии хотя бы одного ожидающего писателя новые читатели также ожидают. Политика исключает бесконечное ожидание писателя при непрерывном потоке читателей.

Условия ожидания:

| Операция | Ожидание, пока истинно | Действие при входе |
|---|---|---|
| `rdlock` | `writer_active` или `waiting_writers > 0` | `active_readers++` |
| `wrlock` | `writer_active` или `active_readers > 0` | `writer_active = 1` |

Алгоритм `unlock`:

1. Определение владельца: при `writer_active = 1` — снятие флага писателя, иначе при `active_readers > 0` — уменьшение счётчика читателей, иначе — возврат `EPERM`.
2. Пробуждение:
   - нет активного писателя и активных читателей, есть ожидающие писатели — `pthread_cond_signal(&writers_cv)`, пробуждение одного писателя;
   - нет активного писателя и ожидающих писателей — `pthread_cond_broadcast(&readers_cv)`, пробуждение всех читателей;
   - в остальных случаях пробуждение не выполняется: ожидающего писателя пробуждает последний выходящий читатель.

Мьютекс удерживается только на время проверки и изменения полей структуры. Работа со списком выполняется без мьютекса, что допускает одновременную работу нескольких читателей. Ожидание на условных переменных выполняется в цикле `while` с повторной проверкой условия после пробуждения (защита от ложных пробуждений и от захвата блокировки другим потоком между сигналом и пробуждением).

### 2.2. Односвязный список

Отсортированный по возрастанию список целых чисел без повторов. Операции:

- `Member` — поиск значения; выполняется под блокировкой на чтение;
- `Insert` — вставка с сохранением порядка, при наличии значения — без изменений; выполняется под блокировкой на запись;
- `Delete` — удаление узла с освобождением памяти; выполняется под блокировкой на запись.

Каждая операция проходит список от начала до первого элемента, не меньшего искомого. Сложность одной операции — O(n), где n — длина списка.

### 2.3. Программа сравнения

Код списка и потоков общий для обеих блокировок; выбор реализации выполняется адаптером (`read_lock`, `write_lock`, `rw_unlock`, `lock_init`, `lock_destroy`). Отличие прогонов — только тип блокировки.

Порядок одного прогона:

1. Построение начального списка из заданного числа случайных ключей (фиксированное начальное значение генератора, одинаковый список для обеих блокировок).
2. Распределение операций между потоками: по `total_ops / P` каждому, остаток — по одной операции первым потокам.
3. Выполнение операций потоками. Тип операции определяется случайным числом из [0, 1) и заданными долями поиска и вставки, доля удаления — остаток до 1. Ключи — случайные числа из [0, 10⁸).
4. Сбор счётчиков потоков и проверка результата: отсутствие ошибок, упорядоченность и уникальность элементов итогового списка, совпадение числа выполненных операций с заданным.

## 3. Пояснения к коду

| Функция | Назначение |
|---|---|
| `my_rwlock_init` | обнуление полей, создание мьютекса и двух условных переменных; при ошибке — уничтожение уже созданных объектов и возврат кода ошибки |
| `my_rwlock_destroy` | уничтожение условных переменных и мьютекса |
| `my_rwlock_rdlock` | захват на чтение по условию из п. 2.1 |
| `my_rwlock_wrlock` | захват на запись по условию из п. 2.1 |
| `my_rwlock_unlock` | освобождение и пробуждение ожидающих по алгоритму из п. 2.1 |
| `rng_next`, `rng_double` | генератор xorshift32 с отдельным состоянием у каждого потока, без общих данных |
| `list_insert`, `list_member`, `list_delete` | операции над списком с указателями `pred` и `curr` |
| `list_size_and_validate` | подсчёт узлов, проверка строгого возрастания |
| `populate_initial_list` | заполнение начального списка |
| `thread_work` | цикл операций потока, счётчики результатов в собственной структуре потока |
| `run_benchmark` | один прогон с выбранной блокировкой, замер времени |
| `main` | разбор аргументов, серия повторов для обеих блокировок, вывод средних значений |

Захват на чтение:

```c
lock->waiting_readers++;
while (lock->writer_active || lock->waiting_writers > 0) {
    rc = pthread_cond_wait(&lock->readers_cv, &lock->mutex);
    ...
}
lock->waiting_readers--;
lock->active_readers++;
```

Захват на запись:

```c
lock->waiting_writers++;
while (lock->writer_active || lock->active_readers > 0) {
    rc = pthread_cond_wait(&lock->writers_cv, &lock->mutex);
    ...
}
lock->waiting_writers--;
lock->writer_active = 1;
```

Пробуждение в `unlock`:

```c
if (!lock->writer_active && lock->active_readers == 0 &&
    lock->waiting_writers > 0) {
    rc = pthread_cond_signal(&lock->writers_cv);
} else if (!lock->writer_active && lock->waiting_writers == 0) {
    rc = pthread_cond_broadcast(&lock->readers_cv);
}
```

Запуск программы:

```
./rwlock <потоки> <всего_операций> <начальные_ключи> <доля_поиска> <доля_вставки> [повторы]
```

## 5. Методика замеров

- Часы: `clock_gettime(CLOCK_MONOTONIC)`.
- Измеряемый интервал: от создания первого потока до завершения `pthread_join` последнего потока. Построение начального списка и инициализация блокировки не входят в замер.
- Параметры нагрузки: 50 000 операций, 1000 начальных ключей.
- Распределения операций (поиск / вставка / удаление): 99,9 / 0,05 / 0,05 %; 80 / 10 / 10 %; 50 / 25 / 25 %.
- Число потоков: 1, 2, 4, 8.
- Повторы: 5 для каждой конфигурации и каждой блокировки, без прогревочных запусков.
- Порядок прогонов внутри серии чередуется: в нечётных повторах первой выполняется библиотечная блокировка, в чётных — собственная.
- Основной показатель: среднее арифметическое времени по 5 запускам. Дополнительно приведены минимальное время и выборочное стандартное отклонение.
- Разница: (T_собств − T_библ) / T_библ · 100 %; положительное значение — собственная реализация медленнее.

## 7. Анализ результатов

- Один поток: время обеих реализаций совпадает в пределах 3 %. Накладные расходы захвата без конкуренции сопоставимы.
- Почти только чтение (99,9 %): библиотечная блокировка ускоряется с ростом числа потоков (с 0,0270 до 0,0132 с при 8 потоках, в 2,05 раза), собственная — слабее (с 0,0278 до 0,0228 с, в 1,22 раза). В собственной реализации каждый `rdlock` и `unlock` захватывает общий мьютекс, и читатели конкурируют за него. В glibc захват на чтение в обычном случае выполняется атомарной операцией без мьютекса. Дополнительно `unlock` читателя при отсутствии ожидающих писателей вызывает `pthread_cond_broadcast` даже при отсутствии ожидающих читателей.
- Смешанная нагрузка, 2 потока: собственная реализация быстрее на 17–20 %. Отдельно причина не исследовалась; возможное объяснение — различие политик приоритета: при приоритете писателей запись не откладывается до момента без читателей.
- Смешанная нагрузка, 4 и 8 потоков: собственная реализация медленнее на 6–71 %. Рост конкуренции за общий мьютекс и более частые засыпания и пробуждения потоков на условных переменных.
- При 10–25 % записей многопоточные прогоны медленнее однопоточного для обеих блокировок. Запись исключительна и при длине списка в несколько тысяч узлов занимает значительное время; остальные потоки на это время простаивают.

## 8. Выводы

Реализована блокировка чтения-записи с приоритетом писателей на основе мьютекса и двух условных переменных. Корректность подтверждена проверками в программе сравнения: отсутствие ошибок, упорядоченность и уникальность итогового списка, полное число выполненных операций во всех прогонах. На однопоточной нагрузке производительность совпадает с `pthread_rwlock_t`; на смешанной нагрузке при 2 потоках собственная реализация быстрее на 17–20 %; при 4–8 потоках и при нагрузке почти из одних чтений библиотечная реализация быстрее до 73 % из-за отсутствия общего мьютекса на пути захвата на чтение.
