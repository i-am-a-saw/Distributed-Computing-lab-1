# Лабораторная работа № 1. Задача № 2: N тел

Студент: Артём Линник. Группа: 23КНТ3

## 1. Задача

Нужно найти траектории N тел, которые притягиваются друг к другу.
Программа получает конечное время `tend` и имя входного файла.
В первой строке файла записано число тел, дальше для каждого тела —
`mass x y z vx vy vz`. Масса должна быть положительной, все числа — конечными.
Используются единицы СИ.

Расчёт идёт в трёх измерениях. По умолчанию в CSV записываются
`t,x1,y1,x2,y2,...`, а в режиме `xyz` — все три координаты каждого тела.
В файл попадают начальное состояние и результаты каждого шага до `tend`.
Если нужно, последний шаг сокращается.

## 2. Как устроен расчёт

В `nbody.h` описаны структуры тела и трёхмерного вектора. Общие функции
вынесены в `nbody.c`: `Read_bodies` читает начальные данные, `Pair_force`
считает силу, `Update_body` обновляет состояние, `Write_state` записывает CSV.
Два основных файла — `nbody_serial.c` и `nbody_pthreads.c` — задают порядок
последовательного и параллельного расчёта.

Сила, действующая на тело i со стороны тела j:

```text
Fij = G · mi · mj · (rj − ri) / |rj − ri|³
G = 6.67430 · 10⁻¹¹
```

В обеих версиях перебираются только пары `i < j`. Сила считается один раз:
к накопленной силе тела i прибавляется `Fij`, а из силы тела j она вычитается.
Так используется третий закон Ньютона `Fji = −Fij` и за шаг выполняется
`N(N−1)/2` расчётов взаимодействия.

Состояние обновляется явным методом Эйлера:

```text
r_new = r_old + v_old · h
v_new = v_old + (F_old / m) · h
```

Сначала вычисляются силы для всех тел, затем меняются координаты и скорости.
Координаты обязательно обновляются по старой скорости.
В последовательной версии это выполняется в одном потоке.

В параллельной версии создаются P рабочих потоков на всё время моделирования.
Поток с номером `rank` обрабатывает строки `i = rank, rank + P, ...`,
а внутри строки — все `j > i`. Каждый поток накапливает силы в своём массиве,
поэтому блокировки на каждой паре тел не нужны.

На каждом шаге используются три барьера: начало расчёта, готовность всех сил
и готовность новых состояний. После второго барьера каждый поток складывает
вклады из всех массивов для своего диапазона тел и обновляет только эти тела.
После третьего главный поток записывает CSV. При завершении он подаёт
сигнал остановки и ждёт рабочие потоки через `pthread_join`.

Работа за шаг занимает O(N²) в последовательной версии и O(N² + PN)
суммарно во всех потоках параллельной версии. Дополнительная память
составляет O(N) и O(PN) соответственно.

## 3. Сравнение результатов

Во время замеров `tools/benchmark.py` сравнивает полученные траектории
последовательной и параллельной версий. Для отдельной пары готовых CSV
используется `tools/compare_csv.py`.

В журнале замеров сохранены 40 сравнений параллельных траекторий
с последовательными. Все они прошли с допуском
`|a − b| ≤ 10⁻¹⁰ + 10⁻¹⁰ · |a|`.
Максимальное абсолютное отличие — около `4.34 · 10⁻¹⁹`.
Журнал находится в `measurements_windows11/comparisons.csv`;
полные траектории этой серии не приложены.

## 4. Условия и методика замеров

Замеры выполнены на ноутбуке со следующими характеристиками:

| Параметр | Значение |
|---|---|
| Модель | Nitro ANV15-51 |
| Процессор | Intel Core i5-13420H |
| Оперативная память | 16 ГБ |
| Основная ОС | Windows 11 Pro 25H2, x64 |
| Среда запуска | WSL 2, Ubuntu 26.04.1 LTS, x86_64 |
| Ядро Linux | 6.18.54.1-microsoft-standard-WSL2 |
| Доступные процессоры в WSL | 12 логических CPU |
| Компилятор | GCC 15.2.0, пакет Ubuntu 15.2.0-16ubuntu1 |
| Библиотеки | POSIX Threads, libm, glibc 2.43 |
| Сборка и замеры | GNU Make, Python 3; точные версии не записаны |

При сборке использовались `-O2 -std=c11 -Wall -Wextra -Wpedantic`,
`-pthread` для параллельной версии и `-lm` для обеих программ.

Для сравнения взяты N=128 и N=2048. Параметры одинаковые:
`tend=1`, `dt=0.0625`, 16 шагов, вывод `xyz`.
Начальные положения заданы на сетке с расстоянием 1000 м, массы —
от 10¹⁰ до 10¹² кг, скорости по каждой оси — от −1 до 1 м/с.
Генератор использует фиксированное зерно `20261015 + N`.

Эта серия замеров сделана до исправления округления времени. При `dt=0.0625`
и до исправления получалось ровно 16 шагов. После правки траектории всех
10 конфигураций побайтно совпали с прежней версией; времена в таблицах
оставлены из исходной серии на ноутбуке.

Для каждого N сравнивались последовательный вариант и Pthreads с P=1,2,4,8
на одном входном файле. Для каждой конфигурации сделан один прогрев,
затем пять измеряемых запусков. В таблицах приведено арифметическое среднее
из пяти запусков. Запуски шли по одному, порядок конфигураций в каждом
раунде перемешивался. Всего получилось 50 измерений без учёта прогревов.

Время измерялось через `gettimeofday` с помощью макроса `GET_TIME` из `timer.h`:

- `Compute time` — сумма времени расчёта отдельных шагов. В параллельной
  версии сюда входят вычисление сил, их объединение, обновление тел и барьеры.
  Запись CSV и создание/завершение потоков в этот показатель не входят.
- `Total time` — время моделирования с записью состояний и закрытием CSV,
  а в параллельной версии — ещё и с созданием потоков и `pthread_join`.
  Чтение входа, выделение памяти, открытие CSV и запись заголовка не учитываются.

Ускорение рассчитано как `S = T_serial / T_parallel`, эффективность —
`E = S / P`. Для них использованы средние `Compute time`.
Полные результаты всех повторов находятся в
[raw_times.csv](measurements_windows11/raw_times.csv), сводка — в
[summary.csv](measurements_windows11/summary.csv).

Время указано в секундах. В столбце «Разброс» — выборочное стандартное
отклонение вычислительного времени, эффективность показана в процентах.

### N=2048

| Вариант | P | Вычисления, с | Разброс, с | С CSV, с | S | E |
|---|---:|---:|---:|---:|---:|---:|
| Последовательный | 1 | 0.609731 | 0.004492 | 0.634265 | — | — |
| Параллельный (Pthreads) | 1 | 0.628472 | 0.002571 | 0.653124 | 0.970 | 97.0% |
| Параллельный (Pthreads) | 2 | 0.325926 | 0.017106 | 0.350313 | 1.871 | 93.5% |
| Параллельный (Pthreads) | 4 | 0.186292 | 0.018704 | 0.210840 | 3.273 | 81.8% |
| Параллельный (Pthreads) | 8 | 0.140641 | 0.002525 | 0.166475 | 4.335 | 54.2% |

Для N=128 два потока дали всего около 1.6% выигрыша. Разница меньше
разброса измерений, поэтому по этой серии нельзя говорить об устойчивом ускорении.
На четырёх и восьми потоках программа работает медленнее последовательной:
в такой маленькой задаче расходы на управление потоками могут перекрывать
выигрыш от параллельного расчёта.

Для N=2048 ускорение уже заметно: на четырёх потоках — 3.27 раза,
на восьми — 4.34 раза при эффективности около 54%.
С учётом CSV на восьми потоках получается ускорение около 3.81 раза.
На одном рабочем потоке версия Pthreads немного медленнее последовательной.
Ожидание на барьерах и объединение массивов сил добавляют работу,
поэтому время не уменьшается строго пропорционально числу потоков.

## 6. Вывод

Результаты последовательной и параллельной версий совпали в пределах допуска.
На задаче из 2048 тел лучший результат среди проверенных вариантов дали
восемь потоков. Для 128 тел распараллеливание заметной пользы не принесло.
Эти результаты относятся к выбранным данным и ноутбуку, на котором шли замеры.

Метод Эйлера прост, но на длинных интервалах и при близких пролётах тел
может давать большую ошибку. Для более точной траектории нужно уменьшать шаг
и проверять, как меняется результат. Столкновения тел в программе не моделируются.
